# docs/TIL — 작업 기록

> 한 번의 작업 묶음이 끝날 때마다 여기에 한 장을 남깁니다.
> **PR 하나 = TIL 한 장**이 기본이고, PR을 만들지 않은 작업(조사·회의 준비 등)도 남깁니다.
> 파일은 **`docs/TIL/<작성자>/` 아래**에 둡니다.
>
> 신설 2026-09-15 (1차 Alpha_Stack `docs/TIL/README.md` 형식을 이어받음)

---

## 왜 쓰나

코드는 git이 남기지만, 그 코드를 쓰기 전에 **무엇을 재 보고 무엇을 버렸는지**는 아무 데도 남지 않습니다.

| 대상 | 얻는 것 |
|---|---|
| **팀원** | 내가 자리를 비운 동안 무슨 일이 있었는지 5분 안에 따라잡는다 |
| **미래의 나** | 발표 준비할 때 "이 숫자 어디서 나왔더라"를 다시 찾지 않는다 |
| **평가자** | 결과물만이 아니라 **과정**을 본다. 이게 포트폴리오의 실체다 |

**결정**(되돌리기 어렵고 나중에 "왜 이렇게 했지"가 나올 것)은 TIL이 아니라
GitHub Discussion의 결론과 ADR로 남깁니다. TIL은 그 결정을 링크만 겁니다.

---

## 파일 이름

```
docs/TIL/<작성자>/YYYY-MM-DD-짧은-제목.md
```

- 폴더는 **작성자 이름**입니다. 네 명이 같은 저장소에 쓰기 때문입니다.
- 날짜는 **KST 기준 작업한 날**입니다. 하루에 여러 건이면 제목으로 가릅니다.
- 제목은 띄어쓰기 대신 **하이픈**을 씁니다.

---

## 형식 — PR을 쓰듯이

아래 6칸을 채웁니다. 빈 칸은 지우지 말고 **"없음"** 이라고 적습니다 — "없음"과 "안 썼음"은 다릅니다.

```markdown
# YYYY-MM-DD · 한 줄 제목

| | |
|---|---|
| 작성 | 이름 |
| PR | #번호 |
| 브랜치 | `type/무엇을-한다` |
| 관련 | Issue · Discussion 링크 |

## 1. 무엇을 했나
## 2. 왜 했나
## 3. 어떻게 했나 — 고른 것과 버린 것
## 4. 어떻게 확인했나
## 5. 막힌 것 · 남은 것
## 6. 배운 것
```

### 쓸 때 지킬 것

1. **숫자는 실측만.** 재지 않았으면 "미측정"이라고 씁니다.
2. **실패도 적습니다.** "세 시간 헤맸고 원인은 X였다"가 가장 값진 한 줄입니다.
3. **버린 선택지를 적습니다.** 고른 것만 적으면 "왜 A를 안 썼지?"가 다시 올라옵니다.
4. **링크를 겁니다.** 코드는 `file:line`, 결정은 Discussion·ADR로.
5. **고치지 않습니다.** 틀린 것이 밝혀지면 새 TIL에서 정정합니다.
